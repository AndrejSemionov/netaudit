# B2.1 — ограниченный запуск экземпляров

Уточнение к B1 §3.2. Для CLI действует лимит запуска `max_parallel` (по умолчанию 4, целое 1–16). Web дополнительно резервирует не более 8 активных экземпляров в процессе; предел одного Web-запуска — `min(max_parallel, 8)`. Один экземпляр старого `params` тоже занимает общий Web-слот. Очередь общая для синхронного, фонового и потокового Web-путей. При освобождении слота ожидание обслуживается по запуску: один слот ожидающему запуску, затем его оставшиеся работники возвращаются в конец очереди. Ожидающий host остаётся элементом входного списка, а не отдельным потоком.

Проверка `max_parallel`, максимум 64 `instances` на check и 256 суммарно делается до запуска первой проверки. Все три прямых API-входа (`/api/estimate`, `/api/run`, `/api/stream/start`) отвечают 400 на превышение. `run_checks_multi` и `run_stream` проверяют это повторно на своей границе. Форма отчёта для одного экземпляра остаётся плоской, для нескольких — `by_host`; порядок ключей равен порядку входных экземпляров, включая суффиксы `#2` у старого API.

Оценка времени суммирует максимумы последовательных групп длиной `min(max_parallel, 8)` в Web и `max_parallel` в CLI. Это приближение: реальное расписание работников динамическое, а очередь других Web-запусков может увеличить ожидание. `total_time` у нескольких экземпляров использует ту же групповую аппроксимацию по фактическим временам. Операционные SSH-таймауты остаются вариантом A, утверждённым USER.

При «Стоп» в Web streaming активная обычная проверка завершается по своим операционным таймаутам, но новые экземпляры после сигнала отмены не запускаются. Ожидающий общий слот worker выходит из очереди без ожидания других запусков. Каждый не начатый host **текущей multi-host группы** остаётся в `by_host` с явной ошибкой `not started: the run was stopped`, временем `0.0` и событием `check_done`; одиночная проверка, ожидавшая слот, получает ту же ошибку в плоской форме. Итоговое событие — `stopped`. Это не объявляет host проверенным.

Синхронный `/api/run` может ждать свободного общего слота, если другие Web-запуски заняли все восемь. Это ожидание входит в HTTP-время ответа и может упереться в timeout обратного прокси; выбранная ранее sync/async оценка не включает нагрузку от других запросов.
