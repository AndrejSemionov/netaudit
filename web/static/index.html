Как пользоваться NetAudit

По каждой проверке: что делает, как запустить из интерфейса, и команда для запуска напрямую в терминале (если проверка — обёртка над системной утилитой).

Установка всех инструментов сразу

Одной командой на сервере, где крутится NetAudit — поставит все системные утилиты, которые используют проверки:

sudo apt install -y mtr-tiny tcptraceroute traceroute iputils-ping dnsutils iputils-arping iperf3 curl openssl iproute2 nmap whois tshark

Можно и по одной, соответствие проверка → пакет:
MTR → mtr-tiny · TCP-трассировка → tcptraceroute · Ping → iputils-ping · DNS (dig) → dnsutils · ARPing → iputils-arping · iperf3 → iperf3 · Заголовки безопасности / внешний web-аудит → curl · SSL-сертификат → openssl · Открытые порты → iproute2 · Захват трафика (tshark) → tshark · Универсальный перехват (ARP) → dsniff и iputils-arping.
Всё это также видно и ставится по кнопке во вкладке «Настройки» → «Инструменты системы».

Сеть

Ping — проверка доступности хоста и задержки.
UI: категория «Сеть» → Ping → задай Target (IP/домен) и Count → «Запустить аудит».
Установка: sudo apt install iputils-ping (обычно уже стоит по умолчанию)
Терминал: ping -c 10 8.8.8.8

MTR (ICMP-трассировка) — трассировка маршрута с потерями пакетов на каждом хопе, лучше обычного traceroute для диагностики нестабильной связи.
UI: Target + Duration (сек) → «Запустить аудит».
Установка: sudo apt install mtr-tiny
Терминал: mtr -r -c 10 8.8.8.8

TCP-трассировка — как traceroute, но по TCP на конкретный порт, полезно когда ICMP блокируют файрволы по пути.
UI: Target + Port + Max hops.
Установка: sudo apt install tcptraceroute
Терминал: sudo tcptraceroute 8.8.8.8 80 (нужен root)

DNS (dig) — DNS-запрос конкретного типа записи.
UI: Hostname + Record type (A/AAAA/MX/TXT и т.д.).
Установка: sudo apt install dnsutils
Терминал: dig google.com A

ARPing — проверка устройства на L2-уровне локальной сети (работает даже если ICMP заблокирован).
UI: Target (IP в локалке) + Count.
Установка: sudo apt install iputils-arping
Терминал: sudo arping -c 5 192.168.88.1 (требует root)

Сайт

HTTP-тайминги — время ответа, DNS/TCP/TLS-хендшейк разбитый по фазам.
UI: URL + метод.
Установка: не нужна, работает через встроенный HTTP-клиент Python.
Эквивалент: curl -w "@curl-format.txt" -o /dev/null -s https://example.com

SSL/TLS сертификат — срок действия, издатель, цепочка доверия.
UI: URL.
Установка: sudo apt install openssl (обычно уже стоит)
Терминал: echo | openssl s_client -connect example.com:443 2>/dev/null | openssl x509 -noout -dates -issuer

Заголовки безопасности — проверка CSP, HSTS, X-Frame-Options и т.д.
UI: URL.
Установка: sudo apt install curl
Терминал: curl -sI https://example.com

Внешний web-аудит (без доступа) — комбинированная проверка сайта снаружи: заголовки, SSL, базовые сигналы — без SSH-доступа к серверу.
UI: URL.
Установка: sudo apt install curl

Проверка SQL-инъекций — пассивное сканирование точек ввода (форм, параметров URL) на признаки уязвимости. Пассивный режим ничего не эксплуатирует, только проверяет реакцию.
UI: URL + режим (пассив/актив) + краулинг (да/нет).
Установка: не нужна, работает без внешних утилит. Используй только на своих сайтах — сканирование чужих без разрешения может быть незаконно.

Сервер (нужен SSH-доступ)

Security-аудит сервера (SSH) — комплексная проверка: firewall, MySQL/MariaDB, SSH-хардининг и другое, всё через один SSH-коннект.
UI: Host + User + Port + Key path (или Password) → «Запустить аудит».
Установка: не нужна на машине с NetAudit (использует paramiko, ставится вместе с самим NetAudit); на целевом сервере ничего ставить не нужно, читает только уже существующие конфиги.
Ручной эквивалент по частям: ssh user@host 'nft list ruleset; grep bind-address /etc/mysql/*'

SSH-аудит сервера — конфигурация самого SSH-демона: PermitRootLogin, PasswordAuthentication, версия протокола и т.д.
UI: те же параметры подключения.
Терминал: ssh user@host 'sudo sshd -T'

CVE-аудит установленного ПО (SSH) — определяет версии nginx/ssh/mysql/php/ядра/wordpress и сверяет с базой уязвимостей OSV.dev.
UI: Host + User + Port + Key path. Запускай вместе с «Security-аудит сервера», чтобы AI-анализ мог сопоставить найденные CVE с реальным конфигом и сказать, что действительно нужно обновить.
Установка: pip install httpx --break-system-packages (нужно на машине с NetAudit, если ловишь ModuleNotFoundError: httpx)
Ручной запуск в Python (на машине с NetAudit): python3 -c "from netaudit_pkg.checks.cve_audit import check_cve_audit; print(check_cve_audit(host='1.2.3.4', user='root'))"

Firewall / Открытые порты — состояние firewall и список слушающих портов на локальной машине (где крутится NetAudit), не по SSH.
Установка: sudo apt install iproute2 (обычно уже стоит)
Терминал (аналог «Открытые порты»): ss -tlnp

Захват трафика

Трафик устройства через MikroTik — снимок текущих соединений устройства (телефона) через SSH к MikroTik, показывает куда идёт трафик прямо сейчас.
UI: IP роутера + User + Password + IP устройства + SSH-порт → «Запустить аудит».
Установка: не нужна, MikroTik сам умеет отдавать эти данные по SSH из коробки.
Ручной эквивалент на самом MikroTik: /ip firewall connection print terse where src-address~"192.168.88.3"

Захват трафика (tshark) — пассивный захват пакетов движком Wireshark на интерфейсе машины, где крутится NetAudit. Нужен root.
UI: интерфейс + длительность + BPF-фильтр (напр. host 192.168.88.55).
Установка: sudo apt install tshark (спросит «Should non-superusers be able to capture packets?» — можно Yes, если нужен запуск не только под root)
Терминал: sudo tshark -i any -a duration:15

Универсальный перехват (ARP + tshark) — работает с ЛЮБЫМ роутером, не только MikroTik. Через ARP-spoofing перенаправляет трафик устройства через машину с NetAudit на время захвата. Специально не вынесен в кнопку интерфейса — требует root без ограничений и является активным вмешательством в сеть (MITM), поэтому запускается только вручную с явным вводом sudo-пароля каждый раз.
Установка: sudo apt install dsniff iputils-arping tshark
cd ~/netaudit && sudo python3 -c " from netaudit_pkg.checks.capture import check_arp_capture import json print(json.dumps(check_arp_capture(target_ip='192.168.88.3', gateway_ip='192.168.88.1', interface='enp0s3', duration=30), indent=2, ensure_ascii=False)) "
Замени enp0s3 на свой сетевой интерфейс (узнать: ip -br addr), target_ip — IP устройства, gateway_ip — IP роутера. Использовать только на своей сети/устройствах.

Производительность

CPU / RAM / диск — снимок загрузки ресурсов локальной машины.
UI: без параметров, просто запускается.
Установка: не нужна, использует библиотеку psutil (ставится вместе с NetAudit).

iperf3 пропускная способность — измерение реальной скорости сети между двумя точками. Нужен запущенный iperf3-сервер на удалённой стороне.
UI: Server (IP другой стороны) + Port + Duration.
Установка: sudo apt install iperf3 — на обеих сторонах (и на машине с NetAudit, и на удалённом сервере)
Терминал (на сервере): iperf3 -s; (на клиенте): iperf3 -c 1.2.3.4 -t 10

Остальные разделы интерфейса

Вкладка «Динамика» — график изменения потерь пакетов (mtr) по выбранной цели во времени, из истории прошлых прогонов.

Вкладка «Настройки» → Anthropic API — ключ для кнопки «AI-анализ: что делать»; История трафика — фоновый сборщик снимков через MikroTik (настраивается там же, работает без кнопки, копит историю в БД); Списки репутации — свои белый/чёрный списки для оценки трафика; Инструменты системы — что установлено, можно доставить недостающее прямо из интерфейса; Пресеты — сохранённые наборы проверок.

Пресеты на вкладке «Аудит» — отметь нужные проверки, нажми «Сохранить как пресет», потом применяй одним кликом сверху над списком проверок.

How to use NetAudit

For every check: what it does, how to run it from the interface, and the terminal command to run it directly (where the check is a wrapper around a system utility).

Install everything at once

One command on the server running NetAudit — installs all the system utilities the checks use:

sudo apt install -y mtr-tiny tcptraceroute traceroute iputils-ping dnsutils iputils-arping iperf3 curl openssl iproute2 nmap whois tshark

Or one at a time, check → package:
MTR → mtr-tiny · TCP trace → tcptraceroute · Ping → iputils-ping · DNS (dig) → dnsutils · ARPing → iputils-arping · iperf3 → iperf3 · Security headers / external web audit → curl · SSL certificate → openssl · Open ports → iproute2 · Traffic capture (tshark) → tshark · Universal capture (ARP) → dsniff and iputils-arping.
All of this is also visible and installable with one click under the "Settings" tab → "System tools".

Network

Ping — host reachability and latency check.
UI: "Network" category → Ping → set Target (IP/domain) and Count → "Run Audit".
Install: sudo apt install iputils-ping (usually already installed by default)
Terminal: ping -c 10 8.8.8.8

MTR (ICMP trace) — route trace with packet loss per hop, better than plain traceroute for diagnosing unstable links.
UI: Target + Duration (sec) → "Run Audit".
Install: sudo apt install mtr-tiny
Terminal: mtr -r -c 10 8.8.8.8

TCP trace — like traceroute but over TCP to a specific port, useful when firewalls along the path block ICMP.
UI: Target + Port + Max hops.
Install: sudo apt install tcptraceroute
Terminal: sudo tcptraceroute 8.8.8.8 80 (needs root)

DNS (dig) — DNS lookup for a specific record type.
UI: Hostname + Record type (A/AAAA/MX/TXT etc).
Install: sudo apt install dnsutils
Terminal: dig google.com A

ARPing — checks a device at the L2 level of the local network (works even if ICMP is blocked).
UI: Target (IP on the LAN) + Count.
Install: sudo apt install iputils-arping
Terminal: sudo arping -c 5 192.168.88.1 (requires root)

Site

HTTP timings — response time broken down by DNS/TCP/TLS handshake phases.
UI: URL + method.
Install: none needed, runs through the built-in Python HTTP client.
Equivalent: curl -w "@curl-format.txt" -o /dev/null -s https://example.com

SSL/TLS certificate — expiry, issuer, trust chain.
UI: URL.
Install: sudo apt install openssl (usually already installed)
Terminal: echo | openssl s_client -connect example.com:443 2>/dev/null | openssl x509 -noout -dates -issuer

Security headers — checks CSP, HSTS, X-Frame-Options, etc.
UI: URL.
Install: sudo apt install curl
Terminal: curl -sI https://example.com

External web audit (no access) — combined outside-in check: headers, SSL, basic signals — without SSH access to the server.
UI: URL.
Install: sudo apt install curl

SQL injection check — passive scan of input points (forms, URL parameters) for signs of vulnerability. Passive mode doesn't exploit anything, only checks the response.
UI: URL + mode (passive/active) + crawl (yes/no).
Install: none needed, works without external utilities. Only use on your own sites — scanning others without permission may be illegal.

Server (requires SSH access)

Server security audit (SSH) — combined check: firewall, MySQL/MariaDB, SSH hardening and more, all over one SSH connection.
UI: Host + User + Port + Key path (or Password) → "Run Audit".
Install: none needed on the NetAudit machine (uses paramiko, installed alongside NetAudit itself); nothing needs to be installed on the target server either, it only reads existing configs.
Manual equivalent, piece by piece: ssh user@host 'nft list ruleset; grep bind-address /etc/mysql/*'

SSH server audit — the SSH daemon's own configuration: PermitRootLogin, PasswordAuthentication, protocol version, etc.
UI: same connection parameters.
Terminal: ssh user@host 'sudo sshd -T'

CVE audit of installed software (SSH) — detects versions of nginx/ssh/mysql/php/kernel/wordpress and cross-checks them against the OSV.dev vulnerability database.
UI: Host + User + Port + Key path. Run it together with "Server security audit" so the AI analysis can cross-reference found CVEs with the actual config and tell you what really needs updating.
Install: pip install httpx --break-system-packages (needed on the NetAudit machine if you hit ModuleNotFoundError: httpx)
Manual run in Python (on the machine running NetAudit): python3 -c "from netaudit_pkg.checks.cve_audit import check_cve_audit; print(check_cve_audit(host='1.2.3.4', user='root'))"

Firewall / Open ports — firewall state and listening ports on the local machine (running NetAudit itself), not over SSH.
Install: sudo apt install iproute2 (usually already installed)
Terminal (equivalent of "Open ports"): ss -tlnp

Traffic capture

Device traffic via MikroTik — a snapshot of a device's (phone's) current connections via SSH to MikroTik, shows where traffic is going right now.
UI: Router IP + User + Password + Device IP + SSH port → "Run Audit".
Install: none needed, MikroTik can already return this data over SSH out of the box.
Manual equivalent on the MikroTik itself: /ip firewall connection print terse where src-address~"192.168.88.3"

Traffic capture (tshark) — passive packet capture with the Wireshark engine on the interface of the machine running NetAudit. Requires root.
UI: interface + duration + BPF filter (e.g. host 192.168.88.55).
Install: sudo apt install tshark (it will ask "Should non-superusers be able to capture packets?" — Yes is fine if you need to run it without root too)
Terminal: sudo tshark -i any -a duration:15

Universal capture (ARP + tshark) — works with ANY router, not just MikroTik. Uses ARP-spoofing to redirect the device's traffic through the NetAudit machine for the duration of the capture. Deliberately not exposed as a UI button — it requires unrestricted root and is an active network intervention (MITM), so it's run manually only, with an explicit sudo password each time.
Install: sudo apt install dsniff iputils-arping tshark
cd ~/netaudit && sudo python3 -c " from netaudit_pkg.checks.capture import check_arp_capture import json print(json.dumps(check_arp_capture(target_ip='192.168.88.3', gateway_ip='192.168.88.1', interface='enp0s3', duration=30), indent=2, ensure_ascii=False)) "
Replace enp0s3 with your network interface (find it with ip -br addr), target_ip with the device's IP, gateway_ip with the router's IP. Only use on your own network/devices.

Performance

CPU / RAM / disk — a snapshot of local machine resource usage.
UI: no parameters, just run it.
Install: none needed, uses the psutil library (installed alongside NetAudit).

iperf3 bandwidth — measures actual network throughput between two points. Requires an iperf3 server running on the remote side.
UI: Server (the other side's IP) + Port + Duration.
Install: sudo apt install iperf3 — on both sides (the NetAudit machine and the remote server)
Terminal (on the server): iperf3 -s; (on the client): iperf3 -c 1.2.3.4 -t 10

Other parts of the interface

"Trends" tab — a chart of packet loss (mtr) over time for a chosen target, from the history of past runs.

"Settings" tab → Anthropic API — key for the "AI analysis: what to do" button; Traffic history — a background snapshot collector via MikroTik (configured there, runs without a button, builds up history in the DB); Reputation lists — your own allow/block lists for traffic scoring; System tools — what's installed, missing ones can be installed right from the interface; Presets — your saved check sets.

Presets on the "Audit" tab — tick the checks you want, click "Save as preset", then apply it later with one click above the check list.
